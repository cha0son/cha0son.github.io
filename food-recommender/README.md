# 🍜 今天吃什么 · 推荐引擎在线演示

**在线体验 → https://cha0son.github.io/food-recommender-demo/**

这是 [food-recommender](https://github.com/cha0son/food-recommender) 的**浏览器移植版**，
用 GitHub Pages 托管，无需后端即可运行。

---

## 这是什么

把 Java 版推荐引擎（`Recommender` 类）移植成 JavaScript，让算法演示能放在静态托管上。

**移植范围**：打分公式、时间衰减模型、场景调整、惩罚项、候选池自适应 —— 逻辑与 Java 版一一对应。

**与原版的两处差异**：

| | Java 版 | 本演示 |
|---|---|---|
| 数据存储 | TSV 文件（`DataStore`） | 浏览器 localStorage |
| 调用方式 | HTTP 接口（`/api/recommend` 等） | 直接调用 `engine.js` 的函数 |

**已做的移植验证**：在 Node 中复现 Java 版跑过的三个实验，结论一致（见下表）。

---

## 三个实验（移植后实测）

### 实验一：时间衰减闭环

固定一道菜（宫保鸡丁，5 星），只改「距上次吃」的天数：

| 距上次吃 | 时间分 R | 结果 |
|---|---|---|
| 0 天 | — | 被硬性排除 |
| 2 天 | — | 被硬性排除 |
| 5 天 | **0.907** | 排名第 1 |
| 10 天 | **0.992** | 排名第 1 |

R 值与公式 `1 − exp(−Δt/λ)`（λ=3）吻合：`1−e^(−5/3)=0.907`，`1−e^(−10/3)=0.992`。

### 实验二：消融实验

同一组数据，只改 β：

| 设置 | 宫保鸡丁（8 天没吃） | 扬州炒饭（4 天没吃） | 分差 |
|---|---|---|---|
| β = 0.30 | 0.943 | 0.852 | **0.092** |
| β = 0.00 | 0.650 | 0.650 | **0.000** |

对照组完全持平 —— 说明时间衰减项确实在起作用，而不是被其他因素掩盖。

### 实验三：候选池自适应

把 26 道午餐类菜品**全部**标记为「今天吃过」：

| | 候选数 | 实际排除天数 | 结果 |
|---|---|---|---|
| 吃之前 | 26 道 | 3 天 | 正常推荐 |
| 全吃遍后 | 26 道 | **0 天**（自动放宽） | 仍能推荐 |

系统没有返回空列表，而是自动降级。

## 文件说明

```
├── index.html     界面结构
├── style.css      样式
├── dishes.js      82 道菜品数据（从 Java 版 DISHES 自动提取，保证一致）
├── engine.js      ★ 推荐引擎移植版，算法核心
└── app.js         界面逻辑 + localStorage 持久化
```

### 想读懂算法，看这三个函数（都在 `engine.js`）

| 函数 | 作用 |
|---|---|
| `preference()` | 偏好分 P：基础评分 + 常吃加成 + 反馈修正 |
| `novelty()` | 时间分 R：`1 − exp(−Δt/λ)`，本项目核心 |
| `score()` | 五项加权求和，得到最终得分 |

`recommend()` 里是**候选池自适应**的实现：候选数不足时逐天放宽排除窗口。

## 本地运行

无构建步骤，起个静态服务即可：

```bash
python -m http.server 8000
# 或
npx serve .
```

然后访问 http://localhost:8000

> 直接双击 `index.html` 也能打开，但部分浏览器对 `file://` 下的脚本有限制，建议用本地服务。

## 界面功能

| 标签页 | 功能 |
|---|---|
| **今天吃什么** | 主推荐卡片 + 完整排名前 15，展示每道菜的**打分明细**（偏好 / 时间分 / 场景 / 惩罚） |
| **菜品库 · 打分** | 82 道菜，点星评分，按菜系 / 状态筛选 |
| **吃过什么** | 历史记录 |
| **算法参数** | 实时调 α / β / γ / λ / 噪声 / 排除天数 / 候选池保底 |

「换一换」每次重新打分，排名会有小幅波动 —— 这是探索噪声在起作用。
